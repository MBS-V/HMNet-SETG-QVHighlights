# Real-data audit — 24 Nov 2026

Scope: this repository (124 files) + the manifests in `/content/qvhighlights` (`video_features` = list of
`{path,key}`, `text_feature` = `{path,key}`, per-file `.npz`). Reproduced on a replica built from real
manifest rows with feature files in the official shapes.

## Root causes
| # | Issue | Root cause | Class | Fix |
|---|---|---|---|---|
| 1 | `TypeError ... not 'dict'` | Manifests use `text_feature={path,key}` (schema of the other project version's `prepare_qvhighlights.py`); this repo's validator **and** `FeatureMomentDataset` only accept a string + `text_key` | validator bug + dataset-loader bug (schema mismatch) | `resolve_ref()` accepts both schemas; used by loader and validator |
| 2 | `video modality length mismatch [(76,2304),(75,512)]` | SlowFast has one trailing clip more than CLIP for some videos; official Moment-DETR truncates every modality to the shortest (`start_end_dataset.py` L205-207) | expected data property; validator/loader stricter than the official pipeline | `load_video_modalities()` = official truncation; differences > 2 rows still error |
| 3 | 2,888 text files missing (33 % train, 32 % val) | Files absent from `text/clip_text_features` (6,946 present vs 10,310 official query ids); uniform loss across splits points to an incomplete copy/extraction | genuine dataset problem | `scripts/audit_text_features.py` restores from Drive copy or official tarball, no overwrite |
| 4 | Backward Mamba sees padding | `torch.flip` on right-padded batches puts padding at the start of the backward scan → outputs depend on batch composition (measured 7e-4 at init) | model bug | `masked_flip()` |
| 5 | `loss_ss` ≈ 74 | Segment–sentence loss sums raw dot products over tokens / 0.07; MESM uses masked mean, L2-normalised cosine / 0.5 | model/loss bug (and FP16 overflow risk) | MESM formulation, τ = 0.5 |
| 6 | best.pt chosen by validation **loss** | train.py | evaluation-protocol issue | `train.select_metric: mAP_avg` (internal metric) |
| 7 | Mixed Mamba backends across sessions | fallback and `mamba_ssm` modules have different weights | runtime hazard | resume refuses if backend differs |
| 8 | Internal mAP ≠ official mAP | non-interpolated AP | evaluation | `evaluate.py` writes official-format files; report the official evaluator |
| 9 | saliency length off by one vs features | annotation clips = round(duration/2) | harmless | truncate/pad with −1 (as Moment-DETR) |

## Not fixed (fidelity notes — decide as a team, change both runs equally)
* Input projection is one `Linear` (paper: "learnable MLPs"); no L2 feature normalisation (Moment-DETR/MESM normalise).
* Classification CE has no background down-weighting (DETR/Moment-DETR use 0.1).
* No per-clip saliency head: saliency loss ranks query–video pairs; highlight-detection metrics cannot be produced.
* Fallback Mamba differs from the official parameterisation (full-rank dt projection, no dt-bias init).
* SE-TG: order-consistency and boundary refinement are **not implemented** (parser, token alignment,
  sub-event embeddings, video alignment, zero-init gate, containment and diversity losses are).
* `clip_sub_features` = CLIP features of ASR subtitles for Moment-DETR pretraining (`pretrain.sh`,
  `subs_train.jsonl`); not query features. Never use them as text features.
